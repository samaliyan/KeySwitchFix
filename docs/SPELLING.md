# Spelling correction

KeySwitchFix 2.9 adds offline spelling correction for Persian and English on
top of the layout repair. It is a **noisy-channel model**, the same
formulation used by production spell checkers, reduced to what fits in a
native tray application with no runtime and no network.

## When it runs

1. The user finishes a word with Space, Enter, Tab, a period, or Shift+Space
   (ZWNJ). Spelling is never evaluated mid-word: an unfinished word and a
   misspelled one are indistinguishable, and the layout repair already covers
   the live case.
2. The layout logic runs first. If the word is a known word in the active
   layout, or its other-layout reading is a known word (a layout mistake or a
   collision), spelling correction is not consulted.
3. Only then is the word treated as a possible misspelling. English is limited
   to all-lowercase words (a capital letter marks a name, an acronym, or code);
   Persian is limited to letter-only tokens (no digits, ZWNJ, or diacritics).
4. Words the user has shown to be intentional are skipped: a word undone with
   Backspace, a word typed twice this session (learned vocabulary, in
   memory), or a word in the optional personal dictionary.

## Candidates

Every string within Damerau–Levenshtein distance one of the typed word is a
candidate: one letter transposed, one letter too many, one wrong letter, one
letter missing. A 10-letter Persian word yields about 700 candidates; each is
one hash probe, so the whole evaluation takes tens of microseconds.

A candidate counts only if it is in the **rank table** for the language.

## Rank tables

`resources/en-rank.bin` and `resources/fa-rank.bin` are open-addressing hash
tables (`KSRT`): 131,072 four-byte slots, each holding a 24-bit fingerprint of
a word and one byte of `round(zipf × 10)`. They hold up to 65,536 words per
language (512 KB each) and are generated by `tools/generate_rank_tables.py`
from wordfreq 3.1.1, the same corpus the common/frequent Bloom tiers use.

The table *is* the spelling lexicon, so its acceptance rule decides what
counts as a real word. Being too strict rewrites valid words; being too loose
keeps corpus typos. Words are examined most-frequent first and accepted when
any of these holds:

1. it is in the base dictionary Bloom (or the short-word lists). The
   common-word Bloom is deliberately *not* trusted here: it is raw corpus
   frequency and contains joined typos such as `alot`. A token that is two
   everyday words run together is rejected only when it is below the casual
   floor **and** at least 2.5 zipf (300×) rarer than both halves: closed
   compounds (`backend`, `signup`, `hotspot`) sit 1.5–2.5 below their halves
   and must stay whole, so the rule prefers missing an `alot` to splitting a
   real word;
2. it has zipf ≥ 4.0 — everyday vocabulary even when a formal dictionary
   omits it (`thx`, `lol`, `pls`, `میخوام`, `چطوری`);
3. no already-accepted word within edit distance one is at least 1.0 zipf
   (10×) more frequent. A rare token next to a very frequent word
   (`teh`/`the`, `recieve`/`receive`, `seperate`/`separate`) is a misspelling
   in the corpus and is kept out; a rare token with no dominant neighbour is
   simply a rare word;
4. it is dominated only by its own stem(s). The Hunspell resources store
   stems, so `kayaks`, `hiked`, `spreadsheets`, `گوشیش`, `کتابهایم` are
   recovered by stripping up to two common suffixes — while `runing`
   (dominated by `running`) or `ther` (dominated by `there`/`their`) are not.

The tables are a build product (they are listed in `.gitignore`);
`build-native.sh` generates them when they are absent, which requires
`pip install wordfreq==3.1.1`. The CI and release workflows do this
automatically. If a build ships without them, spelling correction is simply
reported as unavailable and everything else works.

## Scoring

```
score(candidate) = 10 · zipf(candidate) + error_model(typed → candidate)
```

The error model rewards the mistakes people actually make:

| Edit | Bonus | Example |
| --- | --- | --- |
| Adjacent-letter transposition | +24 | `teh` → `the`, `نسهخ` → `نسخه` |
| Wrong letter, Persian homophone (ح/ه، ت/ط، س/ص/ث، ز/ذ/ض/ظ، ق/غ، ا/آ/أ/إ/ع، ی/ئ، و/ؤ) | +30 | `صلام` → `سلام` |
| Wrong letter on a neighbouring key | +24 | `wprd` → `word`, `خانع` → `خانه` |
| Wrong letter elsewhere | +6 | |
| Extra letter that doubles its neighbour | +22 | `helllo` → `hello`, `سلاام` → `سلام` |
| Extra letter from a neighbouring key | +18 | |
| Extra letter elsewhere | +8 | |
| Extra letter at the very end (suffix stripping: `webs` → `web`) or a Persian initial ن/ب/م | Aggressive only, +0 | |
| Missing letter that would double its neighbour | +24 | `adress` → `address` |
| Missing letter elsewhere | +10 | `wrd` → `word` |

Dropping the final letter is excluded below Aggressive on purpose: it is how a
valid plural, inflection, or name that happens to be missing from the lexicon
would "become" its stem. Doubled final letters (`worldd`) are still repaired.

Keyboard neighbours are computed on the physical QWERTY grid; Persian letters
are mapped to the same keys, so one geometry serves both languages.

## Beyond one letter: joins

Two repairs go beyond a one-letter edit because they are the most common
Persian and English typing mistakes of all:

- **Missing half-space (ZWNJ).** The base dictionary stores ZWNJ-free
  spellings, so `میپرسیدند` is a "known" word even though the standard form
  is `می‌پرسیدند`. When a Persian word starting with `می`/`نمی` is not itself
  an everyday word in the frequency table and the remainder is a frequent
  verb-shaped stem (ending in a personal ending or a past-stem ت/د), the
  joiner is restored. Nouns that merely start with `می` (`میهمان`, `میدان`,
  `میخانه`) fail the verb-shape rule and are left whole. Suffix joins
  (`کتابها` → `کتاب‌ها`) are offered only in Aggressive mode, because many
  nouns end in `مان`/`شان`/`ات`.
- **Missing space.** `inthe`, `alot`, `درخانه`: when an unknown word splits
  into two very common words (zipf ≥ 4.0, or ≥ 5.0 in Conservative; a
  one-letter left half must be `a`/`I`), the pair is a candidate scored by its
  rarer half plus 12 — below every genuine error-model bonus, so a split never
  outranks a one-letter repair that has real evidence behind it.

## Decision

The best candidate wins only if all of these hold for the chosen level:

| Level | Minimum zipf of winner | Margin over runner-up | Minimum word length | 3-letter words need error-model support ≥ |
| --- | --- | --- | --- | --- |
| Conservative | 4.0 | 20 | 4 | — |
| Balanced (default) | 3.0 | 12 | 3 | 18 |
| Aggressive | 2.2 | 6 | 3 | 0 |

The margin is what keeps genuinely ambiguous tokens untouched: `ther` sits
between `there` and `their`, so Balanced leaves it alone. The 3-letter rule
stops abbreviations that are not in the table from being rewritten by a
low-information substitution.

## Where it does not run

Layout repair works everywhere, but spelling correction is skipped below
Aggressive in common code editors and terminals (Windows Terminal, cmd,
PowerShell, VS Code, Visual Studio, JetBrains IDEs, Sublime, Notepad++, SSMS,
DBeaver, Git Bash, WSL, …), where identifiers such as `bool`, `endl`, or
`async` sit one edit away from a frequent word. The user-editable **Excluded
apps** list still disables everything.

## Undo and learning

A spelling fix is an ordinary correction for Undo: one plain Backspace right
after it restores the typed spelling (and consumes the Space). Undoing a
spelling fix also marks the typed word as the user's own for the rest of the
session (a 64-entry ignore list plus the learned vocabulary).

The **learned vocabulary** is a 1,024-entry in-memory ring. A word that the
model examined and left alone — in a context where it would have corrected
it, so never in developer tools, password fields, or with spelling off — is
observed; a word typed twice is treated as intentional and never corrected
afterwards. Names,
jargon, and project vocabulary therefore stop being candidates after their
second appearance without any user action. It lives only in process memory.

The **personal dictionary** is opt-in (**Remember undone words** on the
dashboard). When it is on, an undone spelling that the user had already typed
or restored before in the session (so a single stray Backspace cannot teach a
typo permanently) is appended to
`%LOCALAPPDATA%\KeySwitchFix\personal-dictionary.txt` (UTF-8, one word per
line, editable by hand, UTF-8 or UTF-16 with BOM; whitespace is trimmed,
duplicates are removed, and the file is compacted to the most recent 1,024
entries) and is trusted across restarts. Nothing else is ever written to
disk.

## Settings

- Dashboard: **Spelling** — Off / Conservative / Balanced / Aggressive.
- Tray menu: **Fix spelling mistakes** toggles between Off and the last level.
- Dashboard: **Remember undone words** — the opt-in personal dictionary.
- `settings.ini`: `[Spelling] Level=0..3`, `LastLevel=1..3`,
  `PersonalDictionary=0|1`.

## Known limits

- The join for `می`/`نمی` cannot see the difference between a verb form and
  a noun whose remainder happens to be a frequent verb-shaped word when the
  noun itself is missing from the frequency table (`میزبانم`). The
  learned vocabulary and Backspace-undo are the safety net; report such
  words and they will be added to the exclusion list.
- Very common ZWNJ-less verb forms (`میخواهم`, `میکنم`) are accepted as
  everyday vocabulary and therefore *not* joined — users who type them that
  way on purpose are not corrected.

- Distance-two errors (`recomendation`) are not attempted; they multiply the
  candidate count by the alphabet size and mostly produce noise without a
  language model.
- An *extra* space (`in ter net`) is not handled; a missing one is.
- No bigram context: `their` vs `there` is a grammar problem, not a spelling
  one, and both are correct words.
- Persian words typed with a ZWNJ are evaluated as their halves; `می‌خواهم`
  is fine because `می` and `خواهم` are both words.
